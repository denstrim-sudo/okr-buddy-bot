# Меньше сбросов на GPT‑4o при аудите

## Что происходит сейчас
По журналу аудита сброс на GPT‑4o вызывают две причины:
- **timeout** — выбранная модель (например, DeepSeek V4 Pro) не успевает ответить;
- **no_tool_call** — модель ответила обычным текстом, а не структурированным ответом.
При любой из них приложение сразу переключается на GPT‑4o, без второй попытки на выбранной модели.

## Что делаем
1. **Обновить список моделей.** Сверить каталог с актуальным списком AIAI.BY, убрать устаревшие и помечать «медленные» (reasoning) модели, чтобы было видно заранее.
2. **Честный бюджет времени для медленных моделей.** Для reasoning-моделей давать больше времени на первую попытку, сокращая запас на запасную модель.

Пока не делаем: повтор на выбранной модели, смену запасной модели, новое сообщение в интерфейсе.

## Технические детали
- `list-ai-models`: обновить каталог по актуальному списку AIAI.BY, флаг `slow` для reasoning-моделей.
- `_shared/ai.ts`: per-model timeout-профиль — для `slow` больший бюджет первой попытки в рамках общего лимита (~150 с), остаток на GPT‑4o.
- Тесты Deno (TDD): каталог без устаревших моделей и с флагом `slow`; расчёт бюджета для slow/обычной модели; fallback по-прежнему на GPT‑4o.
- Деплой функций, реальный аудит на 2–3 моделях для проверки.
