# Почему падает вызов edge function на «не-GPT-4o» моделях

## Что удалось воспроизвести

- Прямой вызов `validate-okr` с моделью по умолчанию (`gpt-4o`) — успех, 200, полный отчёт.
- Тот же вызов с `gemini-2.5-pro` — ответа нет вообще, запрос обрывается по таймауту (`context canceled`). Это ровно то, что в браузере выглядит как «ошибка вызова edge function» / «Failed to send a request to the Edge Function».
- В логах edge-функций записей об ошибках нет — функция не возвращает ошибку, она «висит» до обрыва соединения. Поэтому пользователь и видит сетевую ошибку, а не понятное сообщение.

## Причина

В `supabase/functions/_shared/ai.ts` бюджет времени и логика fallback устроены так, что «медленная» модель убивает весь запрос:

1. Таймаут одной попытки — 90 секунд. Попыток в худшем случае три (основная, retry, fallback), суммарно до ~270 секунд. Соединение с браузером рвётся раньше, чем функция успевает ответить.
2. Fallback на `gpt-4o` включается только для кодов `model_unavailable`, `provider_unavailable`, `timeout`, `network_error`. Самые частые проблемы «чужих» моделей — `no_tool_call` (модель не поддерживает function calling так же, как OpenAI) и `invalid_json` — под fallback не попадают: делается ещё один заход в ту же модель, и время тратится впустую.
3. Нет общего дедлайна на весь запрос — только на отдельную попытку.

Итого: gpt-4o работает, а Gemini/Claude «периодически отваливаются» — это не случайность, а закономерное превышение бюджета времени.

## Что делаем

1. **Общий дедлайн запроса.** Ввести бюджет ~55 секунд на весь `runWithFallback`. Таймаут одной попытки — 25 секунд для выбранной пользователем модели и 40 секунд для финального fallback на `gpt-4o`. Функция всегда возвращает ответ до того, как оборвётся соединение.
2. **Fallback по всем невосстановимым кодам.** Добавить в fallback-условие `no_tool_call`, `invalid_json`, `aiai_error`, чтобы «медленная или неподдерживающая tool calling» модель сразу уходила на `gpt-4o`, а не тратила лишний круг.
3. **Убрать лишний retry в ту же модель.** Порядок попыток: выбранная модель → (при любой ошибке) `gpt-4o` → один retry `gpt-4o` только если остался бюджет времени.
4. **Понятная ошибка вместо обрыва.** Если бюджет исчерпан, вернуть 504 с русским текстом («Модель X не ответила вовремя, попробуйте GPT-4o») плюс `_meta`, чтобы UI показал тост вместо «ошибки вызова edge function».
5. **Клиент.** В местах вызова (`OkrGenerator`, `OkrValidator`, `useSolutionStudio`) показывать текст ошибки из тела ответа, а не generic-сообщение; сетевой сбой отдельно подписывать как «превышено время ожидания».

## Технические детали

- Файл `supabase/functions/_shared/ai.ts`: параметризовать `REQUEST_TIMEOUT_MS` (передавать per-attempt), добавить `deadlineAt` в `runWithFallback`, расширить `shouldFallbackToDefault`.
- Тесты (Deno, `_shared/ai.test.ts`): новые кейсы — fallback при `no_tool_call`; отсутствие второй попытки в ту же модель; выход по дедлайну с кодом 504 и корректным `_meta.fallback_reason`.
- Фронтенд: единый разбор ошибки invoke (`error.context?.status`, тело `{ error }`) — маленький хелпер, чтобы не дублировать в трёх местах.
- Каталог моделей и `list-ai-models` не трогаем — они работают штатно.
