# Меньше сбросов на GPT‑4o при аудите

## Что происходит сейчас
По журналу аудита сброс на GPT‑4o вызывают две причины:
- **timeout** — выбранная модель (например, DeepSeek V4 Pro) не успевает ответить;
- **no_tool_call** — модель ответила обычным текстом, а не структурированным ответом.
При любой из них приложение сразу переключается на GPT‑4o, без второй попытки на выбранной модели.

## Что предлагаю
1. **Повтор на выбранной модели перед сбросом.** При no_tool_call — одна повторная попытка на той же модели с подсказкой «верни ответ через инструмент». Если пришёл текст с JSON — пробуем разобрать его сами, без повтора.
2. **Обновить список моделей.** Сверить каталог с актуальным списком AIAI.BY, убрать устаревшие и помечать «медленные» (reasoning) модели, чтобы было видно заранее.
3. **Честный бюджет времени для медленных моделей.** Для reasoning-моделей давать больше времени на первую попытку, сокращая запас на запасную модель.
4. **Запасная модель — по выбору.** Оставить GPT‑4o по умолчанию (правило проекта), но если она отказывает у AIAI.BY, пробовать следующую стабильную модель (например, Claude Sonnet). Меняю только с вашего согласия.
5. **Понятное сообщение в интерфейсе:** «Выбранная модель не ответила вовремя — использована GPT‑4o», с причиной.

## Технические детали
- `_shared/ai.ts`: retry на requested-модели при `no_tool_call`/`invalid_json`; разбор JSON из `content`; per-model timeout-профиль.
- `list-ai-models`: обновить каталог, флаг `slow`.
- Тесты Deno в `_shared/ai.test.ts` (TDD): повтор на выбранной модели, разбор JSON из текста, fallback только после исчерпания.
- Деплой функций, реальный аудит на 2–3 моделях для проверки.
